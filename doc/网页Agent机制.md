# EasyWork 网页 Agent 机制

本文只定义网页 Agent 的职责、每轮上下文、资料目录、读取边界与 Work 交接原则。鉴权、持久化身份、版本号、审计字段和前端排布不进入模型上下文。

## 1. Chat 与 Work 的职责

Chat 中的网页 Agent 直接理解并回答用户问题。它可以读取当前账号有权访问的 Skill、文件、记忆和本轮明确引用的对话，但只读取完成当前回答所需的正文。

Work 中的网页 Agent 是资料收集和中转角色。你应先理解用户真正希望远端 Agent 完成的目标，再从已提供的资料目录中找出可能影响该目标的内容，读取必要正文，并把原始用户请求和选中的资料交给远端 Agent。

你不替远端 Agent 制订执行方案，不操作 SSH、工作区、任务或远端配置，也不把自己的推测写成远端事实。没有检索到相关内容时，直接提交空资料集合，让远端 Agent 依据原始请求继续工作，不猜测不存在的资料。

Work 的正式回答来自远端 Agent 的 final；网页 Agent 不在远端完成后再次改写答案。

两种模式分别读取 `prompts/web/system-chat.md` 和 `prompts/web/system-work.md`，不再拼接共用的 `system.md` 与模式配置。Chat 不注入 Work 的服务器、工作区或远端 Agent 状态；技能目录表示可用的操作规范，不能据此确认对应应用已经部署在当前环境。

## 2. 一次运行的上下文

主机在每条用户消息开始时冻结一次上下文快照。本轮所有模型调用和工具往返复用同一快照；下一条用户消息到来时重新计算权限、目录和状态。

模型上下文按下列语义层次组织：

1. 系统提示词与当前模式职责；
2. Work 当前服务器、工作区和远端 Agent 状态；
3. 当前可见 Skill 目录；
4. 当前可见文件目录；
5. 当前可见的有效记忆事实；
6. 较早网页消息的续写摘要；
7. 当前分支尚未压缩的用户消息与正式助手正文；
8. 当前分支仍有效、且网页 Agent 先前已经读过的知识正文；
9. 本轮用户明确固定的对话引用以及手动选择项；
10. 当前用户原始提问。

工具定义由 API 的 tool 字段单独提供。消息 ID、Task ID、内部版本、权限规则、投递收据明细、切换检测和前端状态不作为自然语言上下文。Work 会用自然语言标明哪些技能和资料已发送给当前远端对话，供网页 Agent 直接复用。

Skill 和文件目录负责让模型知道“有什么可读”；正文工具负责按需取得“具体内容”。记忆目录则直接包含事实正文，其自动带入与检索边界见第 6 节。目录必须覆盖本轮全部可见项，不能用固定条数静默截断并让模型误以为已经看全。若提供方确实无法在一次请求中容纳完整目录，应明确返回分页或上下文过大错误。

## 3. 网页对话上下文

网页消息正文不可变。编辑、重试、分支和回溯通过新快照改变当前可见消息链，不改写历史记录。

当前分支的上下文由较早消息的续写摘要，以及尚未压缩的用户提问和正式助手正文组成。续写摘要保存目标、已确认事实、有效约束、当前进展和未完成事项，不代替原始消息、文件、记忆或远端原生历史。压缩切点不能拆开一组直接问答。

网页 Agent 每轮仍理解同一网页对话的上下文，但系统提示词不向它解释远端原生会话的收据、切换和补发机制。

新对话以首问短预览作为临时标题。首轮正式回答保存后，使用本轮网页模型依据首问和回答生成正式标题；中文最多 14 个汉字，英文最多 14 个单词。用户手动命名优先，后续普通提问不重复生成标题。

## 4. Skill 目录与读取

网页 Agent 每轮直接获得当前账号和模式下全部可用 Skill 的目录，不先调用目录查询工具。Work 还按当前服务器范围过滤；Chat 不按连接服务器裁剪技能。

Skill 是否适用于 Chat、Work、某类服务器或调度器，只读取用户技能库中保存的结构化适用范围；后端不从名称、作者说明或发现简介猜测适用范围。没有配置适用范围的 Skill 默认对两种模式和所有服务器类型可见。

每个目录项包含 Skill 名称和上传时保存的简介；Work 中已发送的技能另标明“已发送到当前远端对话，可直接复用”。市场技能安装时携带市场已保存的简介，个人上传或编辑的技能使用其当前保存的简介。对话直接复用这份内容，不为每个用户重新调用模型生成另一份“发现简介”，也不在聊天时后台补生成。市场内容后续变化不会改写用户已经安装的副本及其简介。

目录模板按模式分开：Work 继续使用 `prompts/web/skill-catalog.json`；Chat 使用 `prompts/web/skill-catalog-chat.json`，说明为“可用 Skill 目录”，以及“标记‘已读取’的技能已经在之前读取过，无需重复读取”。Chat 根据当前对话分支的已读记录标记“（已读取）”，仅在记录与当前安装内容一致时保留标记，并自动带入已读正文；新建聊天不继承其他聊天的已读状态。

目录不包含内部 Skill ID、安装路径、市场状态、强制列表或投递收据明细。Chat 对需要且尚未读取的技能按需读取，优先复用已有正文。Work 判断尚未发送的 Skill 可能相关后，使用正文读取工具取得入口正文；读取已发送技能时，工具明确提示其已发送，本轮不再列为新的下发材料。技能包中的附件仍随远端部署交付，网页工具向模型展示的主要是入口说明。

Work 中用户本轮手动选择的 Skill 和强制启用的 Skill 不由网页 Agent 重复判断。技能只按 ID 选择，读取和下发均使用用户技能库的当前内容，不保留可选的历史版本。强制项和网页按需选择项在当前远端绑定已有该技能时直接复用；用户在输入栏明确重新附加技能时，才再次下发当前安装内容并调用。尚待后端补齐的强制项不列入待选目录，已发送的强制项仍显示复用状态。Chat 中适用于全部模式的强制技能仍按需读取，不套用远端的强制投递流程。

## 5. 文件目录、上传简介与正文读取

网页 Agent 每轮直接获得全部可见文件目录。权限已在后端完成，目录项不重复标注“当前项目”“用户所有”等来源身份。

每个目录项只包含文件名（同名时附最短可辨识相对路径）和一句能区分用途及内容的简介。目录不显示内部文件 ID、结构化标签、关键词、大小、时间、集合绑定或存储位置。检索索引可以使用文件名、简介、正文和分块向量，但这些字段不占用模型上下文。

文件进入资源库时同步生成简介。普通文件由 LLM 阅读完整解析正文后总结；长文件先按结构分块，可以用 embedding 选择覆盖主题、章节和结论的片段，再由 LLM 生成统一简介。简介说明文件是什么、主要包含什么以及适合回答哪类问题，不能只复制开头或文件名。简介与内容摘要绑定；生成失败时写入明确失败，不以截断前缀冒充简介，也不转为后台悄悄补写。缺少当前 LLM 简介的记录不进入目录。

网页 Agent 依据目录判断，再用语义检索或精确读取取得正文。零命中就是没有找到，不生成替代事实。

Work 中用户手动添加的文件属于确定性输入。后端直接把真实文件投递到当前远端 Agent 对话的私有目录，并把可读路径交给远端 Agent；网页 Agent 不负责总结、选择或替代发送。自动可见文件仍由网页 Agent 按需读取和选择。

## 6. 记忆目录

### 6.1 每轮自动带入

网页 Agent 每轮直接获得当前作用域内全部可见、仍有效的记忆事实。主机以空查询读取完整集合，再排除当前对话或分支历史中已经表达的事实，并按内容去重；这一步不按当前问题做相关度检索，也不按检索结果条数裁剪。

每条模型可见记忆只是一条原子事实，例如：“用户希望所有论文引用保留 DOI 链接。”模型不需要看到来源对话、内部层级、确认人、置信度、时间、语义键或版本号。权限、范围、冲突、来源和失效由后端处理。

Chat 可从这些事实中选用与回答相关的内容；Work 将它们作为可选资料，只交付本轮选中的相关记忆。自动带入网页上下文不等于把全部记忆发送给远端 Agent。

### 6.2 按问题检索

记忆库本身支持检索。提供查询时，底层记忆服务结合语义向量、标题与正文词法匹配排序，过滤低相关度结果并抑制近重复内容。未配置或暂时无法使用 Embedding 时，仍可按标题与正文词法匹配检索。检索只使用对应作用域或明确指定版本集合中的有效记忆，不扩大访问范围。

当前网页 Agent 的工具入口有明确边界：

- 常规 Chat 和 Work 均未注册独立的 `memory_search` 工具；模型在已经带入的事实中判断相关性，不额外搜索整个记忆库。
- 用户本轮通过 `@` 明确引用其他对话时，Chat 和 Work 才提供 `conversation_reference_search`。网页 Agent 用当前问题调用它，后端先按引用冻结消息链的来源证据确定记忆版本，再检索其中相关的记忆，并返回该引用的最近上下文及必要的较早完整回合。已在当前可见记忆中出现的同语义事实不重复返回，具体边界见第 7 节。
- 后端 `searchContext` 也支持指定 `sources: ["memory"]` 的查询能力，但它不是当前网页模型可直接调用的独立记忆搜索工具。

因此，“每轮自动带入有效记忆”和“按问题检索引用对话的记忆”是两条不同路径，不能将前者理解为记忆库不支持检索，也不能将后者写成网页 Agent 可以任意搜索全部记忆。

### 6.3 记忆的使用与保存边界

记忆用于恢复此前形成且仍有效的事实、偏好、约定和讨论脉络，不构成本轮新增任务，也不改变当前权限与执行边界。只有与当前请求一致且仍适用的记忆参与判断；与当前请求或更新证据冲突时采用当前明确内容。

只有会改变未来回答或执行方式的稳定事实进入记忆，例如长期偏好、项目约定、已经确认的环境事实和持续有效的决定。一次性任务状态、文件当前内容、命令输出、作业统计、临时错误、模型推测和未采纳建议不属于长期记忆。

当前网页对话已经通过消息历史表达的事实不再以记忆副本重复注入。其他对话产生的事实只有在用户、项目和记忆模式允许时才自动可见；对话级事实不会自动跨对话传播。用户显式引用其他对话时，可按第 7 节限定的来源与冻结边界检索其相关记忆。相同语义只投影当前有效版本。

## 7. 显式对话引用

用户输入中的对话引用在发送时冻结，绑定来源对话、来源分支、来源快照和当时标题。来源对话后续追加、重命名、编辑或回溯不改变已经发送的内容边界。

模型先看到仅用于本轮检索的短句柄和冻结标题，不预先复制整段对话，也不生成一份替代正文的引用简介。引用检索以当前问题为查询，在冻结消息链中先定位由该对话内容形成的相关记忆，再提供冻结边界前最近不超过十个已完成回合；这些内容不足时，继续对更早的完整回合进行语义检索。命中一个回合中的任一内容时返回整个回合，长结果通过显式游标继续取得，不能静默截断。

来源记忆按其原始对话和消息证据筛选，不重新提取或复制；已失效的版本以及当前作用域已有更新事实的同语义旧版本不再投影。一次性细节即使没有进入长期记忆，仍可由最近上下文和冻结原文检索取得。

记忆事实不需要携带发言角色。最近上下文和原文回合必须在模型输入中保留 `user` 与 `assistant` 的结构化角色，使旧助手建议不会被误认为用户约束；这些消息作为引用资料存在，不能拼接成当前对话的真实消息历史。推理、工具调用、运行日志、前端状态和系统消息不属于引用正文。

引用只在包含它的当前用户消息中有效，不自动变成长久记忆，也不在后续消息中继续注入。Work 只向远端 Agent 交付网页 Agent 从该引用中选中的相关记忆或完整消息单元，并清楚标明其为历史资料。

## 8. 读取与选择原则

网页 Agent 以用户目标为中心进行正向检索：

- 先利用完整目录判断可能相关的少量来源；
- 对候选读取足够正文以确认相关性和适用边界；
- 已取得足够资料时立即回答或提交；
- 没有相关目录项，或正文读取仍未找到相关内容时，按空资料继续；
- 不为凑足资料扩大查询，不凭近似措辞编造关联；
- 不按固定工具轮数或输出长度生硬截断仍可取得可靠证据的读取。

同一工具和完全相同参数在一轮内只执行一次。已经读过且内容未变的正文可由分支已读账本重新投影；内容变化、文件后续区段或新的显式引用仍可读取。目录项和零命中不进入已读正文账本。

已读标记不等于禁止所有底层读取。模型跨轮再次调用，或在同一轮换了查询参数时，当前实现仍可能先执行工具，再过滤已知正文，回复“没有新增内容”；相同正文不再次注入上下文，也不重复生成前端“查阅资料”条目。

## 9. Work 的确定性交接

Work 的最终交接由当前用户原始请求、用户手动选择和后端强制启用的必需内容，以及网页 Agent 本轮明确选中的记忆、文件正文、对话引用和 Skill 合成。

网页 Agent 只提交选择结果，不重写用户目标。后端在创建远端 Task 前完成权限复核、技能当前安装内容解析、文件版本固定、去重和真实文件准备；任何必需项准备失败时本轮明确失败。

同一远端原生会话会记住已经发送的提问和原生执行历史，后端不重复补发网页上下文。只有网页对话切换到另一个远端 Agent 对话时，后端才按目标会话的已交付边界补发其缺少的用户提问和正式助手正文，并标注为历史记录。再次切回旧会话时只补发离开期间新增正文。该逻辑完全在后端完成，不进入网页 Agent 上下文，也不在前端展示。

远端知识收据避免未变化的记忆、文件正文和引用资料重复发送给同一原生会话，并向网页 Agent 明示已发送的内容。未确认交付的失败任务不能形成收据。Skill 根据当前绑定已有的技能文件判断可否复用；自动选择不会反复下发或调用同一技能，用户本轮手动附加仍执行原生调用。

## 10. 状态与故障边界

一次运行的目录、权限和服务器状态采用同一个冻结快照。下一条用户消息才观察新状态。

运行事件、流式文本、工具操作、作业状态和正式回答分别保存。页面重连可以恢复这些投影，但运行事件不自动成为网页历史或长期记忆。

目录生成、文件简介、必需投递、引用读取或远端启动失败都应保留明确错误边界。主机不能把缺失内容伪装为零命中，也不能让网页 Agent 用想象补齐。
