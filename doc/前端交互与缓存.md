# EasyWork 前端交互与缓存

本文记录页面状态、列表缓存和显示规则；它们不进入模型提示词。对话图片、流式显示和重试见《网页 Agent 机制》，远程连接见《SSH 机制》。

## 1. 技能页面

个人技能、市场及上传审核列表分别缓存。上传列表还区分用户或访客、管理员或普通成员，以及待审核、已审核页签，不能用一个列表覆盖不同审核范围。

列表请求按各自的请求代次应用结果，旧请求不能覆盖后发请求。进入页面时先显示已有缓存，并对当前页签重新校验；上传、审核和删除会失效对应列表。审核完成立即移除旧条目，再刷新已审核页，避免待审核条目再次出现。Chat 专用技能不展示 Work 的强制启用配置；输入栏选择技能只提交技能 ID。

## 2. 网页模型与 Qoder 目录

网页输入栏显示与实际发送共用 `resolveWebModelSelection`。保存的 API 提供方仍存在时沿用该选择；提供方被删除后选择当前列表中的首项，并只读取该提供方自己保存的模型，不沿用已删除提供方的模型 ID。新提供方没有已选模型时要求用户选择；没有提供方时要求先配置 API。

账户面板加载 API 列表时显示加载状态；删除成功立即从统一 bootstrap 中移除该提供方，再刷新列表。模型菜单正在浏览的提供方消失时返回提供方列表，不保留失效的模型页。

Qoder CN 的目录来自服务器上登录账号的原生接口。前端缓存按 Actor、服务器和 Qoder 账号域分开，稳定键不依赖稍后才到达的 Agent 安装版本；兼容迁入旧键下最新的有效缓存。切换服务器时只显示目标缓存，不能短暂显示另一服务器的模型或积分。目录未读取成功或某个模型消失时，页面显示“正在读取模型”或“当前模型”，不直接展示 `qmodel_*` 内部 ID。具体缓存期限和原生协议见 `agent/Qoder-CN.md`。
