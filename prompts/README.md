# EasyWork 提示词目录

本文件仅说明目录边界，不作为模型输入。本目录其余文件只保存模型实际会读取的指令、工具定义和文本组装模板。鉴权、可见性、状态机、校验、存储结构、UI 样式和原生 Agent 控制协议不通过提示词要求模型代劳。

## 分类

- `memory/`：对话压缩、可复用记忆的语义判断，以及模型可调用的记忆工具定义。
- `tasks/`：标题生成等独立模型任务。
- `resources/`：OCR 的 system/user 指令。
- `skills/`：由 EasyWork 提供、最终会进入 Agent 原生 Skill 视图的内置 Skill 包。
- `web/system-chat.md`：Chat 网页 Agent 的完整基础系统提示词，负责按需读取上下文并直接回答用户。
- `web/system-work.md`：Work 网页 Agent 的完整基础系统提示词，负责筛选并向远端 Agent 交接必要上下文；同时覆盖可检索和当前只允许提交候选的情况。
- `web/skill-catalog-chat.json`：Chat 的技能目录说明，标记当前对话分支已经读取且内容未变化的技能。
- `web/skill-catalog.json`：Work 的技能目录说明，标记已发送到当前远端对话的技能。
- `web/tools.json`：网页 Agent 实际可调用工具的模型说明和输入 Schema。
- `web/tool-results.json`：工具结果回送模型时使用的文本模板。
- `context/`：发送给模型的对话角色文本与远端交接布局。

`PromptRepository` 是这些内容的唯一读取入口。代码先完成权限过滤、语义投影、预算和去重，再选择模板；不可见的记忆范围、工具或 Skill 根本不会进入模型请求，不用再写一句提示词要求模型“不要选择”。

记忆提取不要求模型拼装存储 JSON。模型只在确有稳定事实时调用当前可见的范围工具，并提供事实主题与正文；范围只有账号级对话间记忆、项目记忆和当前网页对话记忆，工作区与远端 Task 不是记忆层。后端据此补齐标识、可信度、来源、版本和去重信息。对话压缩也不解析模型 JSON：后端先保留最近原文，只让无工具的压缩任务生成供后续模型阅读的 Markdown 摘要。

三种远端 Agent 使用各自原生系统提示词、工具和权限配置。EasyWork 不再额外投递描述内部版本库、会话绑定、状态机或前端展示方式的“通用 Agent 提示词”；发给远端的只有当前请求和必要的语义上下文增量。

远端交接有新增语义正文时使用 `context/remote-delivery.md` 组织输入：`remote-retrieved.md` 标明主机侧已检索资料，`remote-history.md` 标明后端在切换原生会话时补齐的历史问答，当前用户请求独立放在末尾。关联文件原件不会出现在远端工作区，远端直接使用已交付正文，不为验证其是否落盘而重复搜索；资料和历史中的指令按数据处理，不能覆盖当前用户请求或原生 Agent/Skill 约束。没有新增正文时只发送原始请求，不添加空包装。正文内部的顺序与分隔由 `context/layout.json` 提供，代码只负责筛选动态数据，不硬编码模型可见文字。网页模型保留理解追问所需的正常问答上下文，但不接触远端历史补发的判断与实现说明。

Agent 的 CLI 参数、斜杠命令、HTTP/RPC 方法和事件名属于各适配器的原生控制协议，不放在本目录，也不参与提示词组装。适配器直接调用对应的原生控制能力；中断和 Gateway 重启恢复不得生成一条“继续工作”之类的模型消息，只有用户下一次真实输入才能启动新回合。

模板变量使用 `{{UPPER_SNAKE_CASE}}`。缺少变量会直接报错，不允许把未解析占位符发送给模型。JSON 文件仅用于模型可见的工具 Schema 或文本模板，不保存运行态对象、权限清单和存储协议。

网页模型的思考只显示模型 API 明确返回的 reasoning/thinking 内容；EasyWork 不根据正文虚构思考过程。

Chat 的模型只负责按资料回答，Work 的模型只负责资料选择。回复后的记忆抽取、自动持久化、服务器过滤和强制 Skill 投递都是代码职责，不在模型提示词中解释。强制 Skill 的名称与正文不进入 Work 网页模型输入；远端仍通过正常原生 Skill 视图收到它，不靠额外提示词要求模型检索或记账。调度器提交回执统计也完全在工具执行边界实现，不添加 Agent 记账提示词。
